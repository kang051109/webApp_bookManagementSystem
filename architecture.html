Book Management System - Architecture Design Document

一、系统架构图 System Architecture

系统采用前后端分离架构。前端 Vue.js SPA 通过 RESTful API 与 Jakarta EE 后端通信， 后端严格遵循三层分层架构（Controller / Service / Repository），数据持久化至关系型数据库。

前端层 - Vue.js SPA
Login / Register BookList / Detail BookForm / Category MyBorrows / Dashboard
RESTful API / JSON
后端层 - Jakarta EE / Servlet
Controller - JAX-RS
AuthResource BookResource CategoryResource BorrowResource DashboardResource
Service - Singleton
AuthService BookService CategoryService BorrowService DashboardService
Repository - JDBC DAO
UserRepo BookRepo CategoryRepo BorrowRepo
数据库层 - MySQL
users categories books borrow_records
横切关注点 (Cross-cutting)
CORS Filter ExceptionMapper JsonResponse PasswordUtil DatabaseUtil

二、数据库 ER 图 Entity-Relationship Diagram

系统包含 4 张核心数据表。users 与 books 通过 borrow_records 建立多对多借阅关系， books 通过 category_id 关联 categories 进行分类。 

erDiagram
    users {
        BIGINT id PK "主键"
        VARCHAR username UK "用户名(唯一)"
        VARCHAR password_hash "密码哈希"
        VARCHAR email UK "邮箱(唯一)"
        VARCHAR full_name "姓名"
        VARCHAR role "角色 user/admin"
        TIMESTAMP created_at "创建时间"
    }

    categories {
        BIGINT id PK "主键"
        VARCHAR name UK "分类名称(唯一)"
        VARCHAR description "分类描述"
    }

    books {
        BIGINT id PK "主键"
        VARCHAR isbn UK "ISBN(唯一)"
        VARCHAR title "书名"
        VARCHAR author "作者"
        VARCHAR publisher "出版社"
        INT publish_year "出版年份"
        BIGINT category_id FK "外键-categories"
        INT total_copies "总库存"
        INT available_copies "可借数量"
        TEXT description "图书描述"
    }

    borrow_records {
        BIGINT id PK "主键"
        BIGINT user_id FK "外键-users"
        BIGINT book_id FK "外键-books"
        TIMESTAMP borrow_date "借阅日期"
        TIMESTAMP due_date "应还日期(14天)"
        TIMESTAMP return_date "归还日期"
        VARCHAR status "状态"
    }

    categories ||--o{ books : "包含"
    users ||--o{ borrow_records : "借阅"
    books ||--o{ borrow_records : "被借阅"
 PK  主键  FK  外键  UK  唯一约束 ||--o{ : 一对多关系
